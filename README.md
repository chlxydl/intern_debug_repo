## 文档维护

每次更新文档时，请保持段落结构清晰，并在提交前检查 Markdown 格式与链接内容，确保读者能够顺畅地获取项目说明。

提交文档变更前，也应确认示例与项目当前行为一致，便于维护者快速复核内容并减少发布后的歧义。

文档改动完成后，请在提交信息中简要说明变更范围，并将构建检查结果一并提供给评审者，以便快速确认内容已准备就绪。

为便于持续维护，文档段落应围绕单一主题组织，并在内容发生变化时同步核对相关示例与说明。

提交前的文档构建检查还应覆盖新增段落的标题层级、列表格式和链接目标，确保变更在自动化发布流程中保持稳定。

文档评审时可结合变更说明与构建检查结果快速定位新增内容，及时发现格式或链接问题。

为保持文档发布流程可追溯，维护者应在完成段落调整后记录检查结果，并在评审中明确说明任何需要后续跟进的链接或示例。

新增文档内容时，应在提交前确认段落与既有章节的语气和术语保持一致，并优先使用可直接验证的说明，帮助评审者快速判断内容是否准确。

完成文档构建检查后，应将检查结论与变更摘要一并保留在评审上下文中，便于维护者复现验证并确认文档可以安全发布。

本次文档更新应在提交前完成可复现的构建检查，并在评审说明中记录检查命令与结果，确保新增内容能够稳定纳入发布流程。

## 变更验证

每次文档提交后，应使用干净的工作树重新执行格式与链接检查，并将通过结果附在评审说明中，方便其他维护者复核变更。
